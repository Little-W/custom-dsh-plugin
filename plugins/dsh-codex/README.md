# Codex 编程助手

全局“模型基础提示词”组件根据 DSH 每一步捕获的模型路由选择基础指令。OpenAI 模型优先加载本机 Codex `models_cache.json` 中同名模型的 `model_messages.instructions_template`，其次使用随插件附带的同名快照；非 OpenAI 模型以及缺少精确模板的模型使用通用基础指令，不借用其他型号的模板。当前打包 10 个模型映射、5 份不同模板。缓存按文件状态刷新，切换模型后的下一次提示词合成会重新选择，不沿用上一个模型的模板。

“提示词渲染与组合”组件参考 OpenCode 的 `SessionSystemPrompt.render`、模型优化插件和 `override/append` 机制，提供 `studioPromptRenderer.render/compose/transform` 服务。所有模型和会话模式都按当前作用域、当前步骤获准工具的实际 schema 生成工具契约，并改写模板中的平台专属调用方式；未注册的外部工具 API 会被 DSH 能力说明替换。所有模式统一使用 DSH 原生 `apply_patch` 作为唯一文件修改接口，工具包通过全局文件系统组合启用；提示词不会把 `edit` 或 `write` 提供为替代工具。PTC 通过原有 `run_code` SDK 调用底层 patch 能力。文件链接统一为确认过的绝对路径加单行 `#L<n>`，清除相对路径、`:line` 与行号范围规则。工具执行器、作业、权限与沙箱规则继续由 DSH 提供。

适配不只替换名称：原模板中的工具专用章节会替换成 DSH 执行约定，并为涉及适配的内置能力生成原生定义块，完整保留当前注册表投影中的 `name`、`description`、`parameters`，包括必填项、类型、枚举和权限字段。其他工具继续使用 DSH 原声明。PTC 将这些定义标记为 SDK 底层能力，不把它们加入直接调用列表；SDK 签名仍由 DSH 原生渲染器生成。`studioPromptRenderer.definitions` 可独立渲染这些定义。

默认 `mode: override` 替换 DSH 的内置基础身份、已知默认 persona 和 Codex 预设身份段；保留专用角色、自定义 persona、模式策略、工具说明和运行上下文。`mode: append` 保留现有段并追加新基础指令。完整自定义 persona 的 `complete` 仍由 DSH 最终处理。`model-prompts` 组件配置支持 `codexCachePath`（自定义本机缓存位置）与 `modelAliases`（显式别名到精确模型标识的映射）。未配置路径时读取 `$CODEX_HOME/models_cache.json`，或 `~/.codex/models_cache.json`。

启用后，通用任务执行策略会全局应用于所有会话模式：理解用户目标并主动推进，用证据修正假设，组合工具探索方案，完成连贯实现和适当验证。遇到阻碍时，应重新检查当前方法的前提，考虑不同的任务分解、工具组合或实现路径，使用小规模实验选择有效方案，持续完成有用工作。

完成声明要求对应实际操作证据：读取已有代码、更新计划、语法检查和 `git diff --check` 不代表修改已发生。源码修改、构建、安装、运行时加载和真实界面验证分别核对；用户反馈问题仍存在时重新诊断。DSH 插件界面可使用“插件页面预览”组件启动独立的原生认证实例，再通过 Chrome 检查真实渲染；手工 HTML/CSS 页面仅作为布局探针。全局执行与验证策略在工作流角色关闭人设段时继续保留，权限和沙箱仍由原生执行层管理。

这套提示词不针对某种错误编写固定命令清单。它鼓励在用户目标和实际执行约束内创造性解决问题，灵活使用 shell、现有脚本、库、SDK 和已连接的服务；PTC 使用当前 SDK 暴露的工具接口。一次方法失败不等于任务不可完成；需要用户介入时，应给出实际证据和最小必要动作，并完成仍可独立推进的部分。计划模式、权限与沙箱、用户约束和目标生命周期仍由 DSH 管理。

启用后，批量文件编辑规则会全局应用于所有会话模式：先检查相关实现、调用方与测试，再把每个文件的完整改动合并到一次 `apply_patch` 调用；不得用 `edit` 或 `write` 替代，也不需要先调用读取工具。全局工具沿用 DSH 原生权限审批、沙箱校验、版本观察和原子变更行为。

`apply_patch` 已由 DSH 原生注册；插件直接包装现有工具定义并调用原执行器，避免同名重复注册导致 Codex 预设启动失败。

Codex 编程预设使用 Codex 风格的编程提示与工具流程：shell 优先、独立检查并行执行、路径核实后读取、限量目录列表、SVG 安全预览、精简计划与上下文压缩后的路径恢复。保留 DSH 专用 `read`、`glob`、`grep` 用于精确、受限的读取和检索；shell 中的 `rg`、`rg --files` 作为灵活搜索方式。该工具选择指引也应用于其他模式。全局工具 schema 过滤会从模型可见工具列表中移除 `edit` 和 `write`，所有文本修改统一使用 `apply_patch`。插件保留 DSH 原版 Bash 工具及其作业管理；图片生成由运行环境提供的独立组件负责，本插件不会声称自行生成图片。

插件还补充了有输出上限的目录列表；读取不存在的路径时，会明确指出未读取到内容，并附上有限的父目录条目，避免模型根据相似文件名猜路径。专用 `grep` 遇到不支持的正则特性时会解释限制并提供 shell `rg --pcre2` 替代；无效模式会按字面内容重试。读取行号超出文件范围时会调整到有效位置。SVG 图片会先经过安全检查，再渲染为 PNG 预览供支持图片输入的模型查看。

复杂任务会采用精简的阶段计划；上下文压缩后，如果文件路径依据已不可见，会重新进行小范围探测。搜索空结果按当前检索范围内无匹配处理，不据此推断文件内容，也避免重复相同的失败查询。Goal 提示遵循 DSH 的权限边界：只有顶层智能体正在处理用户直接消息时才执行目标变更，恢复轮次和子智能体由目标驱动器处理。Windows 使用 PowerShell，其他系统使用 DSH Bash。

全局行为组件只依赖 DSH 的 `systemPrompt`，不依赖某个预设的工具集；通过独立提示段和 Bash/PowerShell 提示补充生效。模型基础提示词组件另依赖 `tools` 与 `studioPromptRenderer`，使用公开的作用域工具投影读取能力，保留工具声明、执行器和权限上下文。Shell 的实际文件探测结果也可作为路径依据。

设计参考本地 `openai-codex`（`78245b4`）的 `codex-rs/core/gpt_5_2_prompt.md`、`codex-rs/core/templates/personalities/gpt-5.2-codex_pragmatic.md` 中持续执行、工程判断与端到端验证原则，以及 `opencode`（`9bbb8ce18`）的 `packages/core/src/plugin/system-prompt/gpt-astra.txt`、`meta.txt`、`kimi.txt` 和 `packages/core/src/session/system-prompt.ts` 中主动完成请求、证据核实、保留用户约束、组合工具和按能力提供指引的设计。这里提炼适用于 DSH 的规则，不整体替换用户人格、模式或权限策略。
