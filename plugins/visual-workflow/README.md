# 可视化工作流

面向 DSH 的智能体工作流插件，用流程图组织任务、角色与团队，查看执行进度，并在需要时调整流程、暂停或继续运行。支持复用模板、智能体辅助编排，以及将工作流作为 OpenAI 兼容 API 服务运行。

本插件基于 **GZX2211 与原项目贡献者的 [dsh-Visual-Workflow](https://github.com/GZX2211/dsh-Visual-Workflow)** 二次开发，作为 [custom-dsh-plugin](https://github.com/Little-W/custom-dsh-plugin) 的一部分维护。在原有可视化编排能力上，增加 DSH 运行时适配、工作流工具改进、知识积累与界面优化。

## 功能

- **可视化编排**：配置角色、任务、团队、数据库与流程阶段，通过连线安排执行顺序、条件分支和任务上下文。
- **角色配置**：为角色设置职责提示词、模型、思考强度、工具组合、输入输出契约，以及执行与重试上限。
- **运行管理**：查看节点状态与输出，记录分支决策，暂停、继续或从指定节点恢复；模板和运行实例分别管理。
- **智能体辅助改图**：搜索已保存的模板，读取准确的图结构与版本，预校验补丁，再一次性提交修改。
- **团队协作**：将不同职责的角色组成 Team，按需调度成员，通过消息交流并向用户提问。
- **模板与资产复用**：管理角色和工作流模板，导入、导出及批量管理模板，召回版本化组织资产和已有经验。
- **知识积累**：将验证过的方法保存为 DSH 技能，记录问题根因与修复教训，供后续任务检索使用。
- **定时执行与 API 服务**：配置工作流触发计划，或将流程作为独立的 OpenAI 兼容接口供外部应用调用。

## 安装与入口

本分支的安装目录是本仓库中的 `plugins/visual-workflow`，包名为 `dsh-visual-workflow`。已在 DSH `0.2.2-rc.1` 环境验证；实际兼容范围以 [package.json](package.json) 为准。

在 DSH 插件管理中安装该本地目录并启用插件，然后从侧边栏的“工作流”入口打开工作台。更新后按宿主提示重载插件或重新启动客户端。

本仓库也提供桌面端安装脚本，在仓库根目录执行：

```sh
node scripts/install-dsh-plugins.mjs --dry-run
node scripts/install-dsh-plugins.mjs
```

该脚本会同时更新仓库中的 **Codex 编程助手和可视化工作流**，通过桌面端的 generation 安装机制替换插件，并保留插件开关设置。只安装工作流时，在插件管理中选择 `plugins/visual-workflow` 目录即可。

插件包含两个可独立启停的组件：

| 组件 | 用途 |
| --- | --- |
| 可视化工作流 | 画布、模板、角色配置、流程运行、API 服务与编排工具 |
| 工作流知识积累 | 技能与错误教训的保存、检索和运行期注册 |

## 开始使用

1. 在工作台中选择已有工作流模板，或创建一个模板。
2. 设置一个启动节点和至少一个结束节点，添加任务所需的角色与流程连线。
3. 为角色填写职责、模型和工具组合；需要额外任务说明时，添加任务节点并连接上下文线。
4. 从模板创建实例，核对工作目录、模型与角色配置后启动运行。
5. 查看节点状态和交付结果；遇到需要人工确认的阶段时暂停，确认后继续。

修改模板用于后续创建实例；修改当前运行应选择对应实例。运行过程中保存的配置会在后续调度时读取，正在执行的模型请求仍遵循 DSH 原生步骤配置。

## 节点与连线

| 节点 | 作用与主要配置 |
| --- | --- |
| 角色 `agent` | 执行具体任务；配置职责 `systemPrompt`、模型、工具组合、输入输出契约和重试上限 |
| 父代理 `parent` | 协调流程、调度角色并汇总结果；运行实例中的当前父代理受修改保护 |
| 团队 `group` | 组织多个不同职责的成员；配置成员清单和协作说明 |
| 任务 `task` | 向角色提供任务正文；`label` 是名称，`content` 才是实际提示词内容 |
| 过程提示词 `step` | 沿流程向后续角色提供过程说明，正文保存在 `content` 中 |
| 数据库 `database` | 提供数据库查询与检索；支持 SQLite、MySQL 和 PostgreSQL |
| 启动、结束、暂停 | 定义入口、收口与人工检查点；暂停节点用于流程编排模式 |
| 别名 `proxy` | 引用一个已有角色，共享其配置和执行实例；不创建另一个智能体 |
| 子流程 `subgraph` | 封装带独立入口和出口的内联流程 |

| 连线 | 含义 |
| --- | --- |
| 流程线 `flow-out → flow-in` | 控制执行顺序，可配置 `pass`、`fail` 或带说明的 `content` 条件 |
| 上下文线 `ctx-out → ctx-in` | 将任务节点正文提供给角色；不会触发角色运行 |
| 数据库线 `db-out → db-in` | 将数据库能力接入角色，供其查询与检索 |

角色会接收直接流程前驱的可用产出；额外的任务正文通过上下文线提供。任务名称、角色名称和描述字段不能代替实际提示词正文。

### 重试与别名

`retryLimit` 表示同一个角色在首次执行之外允许的重试次数。要求“设计师回流重试 5 次”时，应保留一个设计师角色并设置 `retryLimit: 5`。`reactLimit` 约束单次调用内部的迭代，两者用途不同。

审查回流使用 `fail` 条件线返回同一个祖先角色，并保留通向结束节点的 `pass` 路径。复审回流预算单独记录，在派发前保存；角色成功输出、暂停或恢复运行不会清空该预算。普通前向流程仍须无环。

proxy 和自动布局生成的 `auto-ref-*` 都按其 `proxySourceId` 对应的角色计算流程可达性与环路。别名可以承接原角色的流程入线或出线，不需要给原角色重复接线。

## 智能体工具

| 工具 | 用途 |
| --- | --- |
| `wf_org_catalog` | 查找已保存的工作流模板，或召回角色、资产、工具组合、模型与编排规则 |
| `wf_graph_patch` | 读取、预校验或原子修改模板和实例 |
| `wf_run_node` / `wf_run_node_wait` | 启动角色任务，分别用于流程编排和 API 服务运行 |
| `wf_wait_agent` | 等待节点结果，不重复派发任务 |
| `wf_decide` | 记录条件分支选择及依据 |
| `wf_resume` / `wf_finish` | 恢复中断流程，或结束运行并保存结果 |
| `wf_ask_user` / `wf_send_message` | 向用户提问，或向父代理及成员发送消息 |
| `wf_db_query` | 执行数据库检索、只读查询或读取结构 |
| `wf_experience_learn` / `wf_experience_recall` / `wf_experience_feedback` | 保存、召回与评价组织经验 |
| `wf_knowledge_capture` / `wf_knowledge_recall` | 保存或检索工作流技能和错误教训 |

工具按角色权限和运行环境提供；改图、调度与组织管理工具由父代理使用。

### 工作流修改流程

将以下参数传给 `wf_org_catalog`，按名称取得真实的 `tpl-*` 模板 id：

```json
{ "templateQuery": "工作流名称或关键词" }
```

随后通过 `wf_graph_patch` 读取该目标：

```json
{
  "action": "read",
  "scope": "template",
  "targetId": "tpl-example",
  "includePrompts": true
}
```

返回值包含已保存的图、版本号、任务正文，以及别名映射和可达性诊断。`tpl-example` 是示例占位符，调用时替换为查到的 id；编辑运行实例时使用 `scope: "instance"` 和实例 id。

准备好操作后，用相同目标和读到的 `expectRevision` 提交补丁：

- `action: "validate"`：检查操作、版本、配置与图结构，不写盘；返回 `readOnly: true`、`validated: true`、`applied: 0`。
- `action: "apply"`：整批校验通过后原子保存，返回新版本和变更清单。

复杂改线应把拆线、接线和条件分支调整放在同一批操作中。任一操作失败，整批都不会保存；不需要撤销仅出现在被拒绝提案里的节点或连线。版本冲突时重新读取同一目标，再调整补丁。

### 知识积累

通过 `wf_knowledge_recall` 的 `guide` 操作读取使用指引，`recall` 检索摘要，`read` 读取具体条目。经过验证的做法可保存为工作流技能，已修复问题可记录为错误教训；同一问题会合并记录。

生成的技能正文保存在 `$DSH_HOME/skills/wf-*/SKILL.md`。组件的配置、存储和维护说明见 [知识积累文档](lib/knowledge/README.md)。

## 数据与配置

默认工作流数据目录为 `$DSH_HOME/visual-workflow/`，可通过插件设置中的 `dataDir` 调整。桌面端以其实际 `DSH_HOME` 为准。

| 数据 | 内容 |
| --- | --- |
| `flow-templates/` | 可编辑工作流模板 |
| `workflows/`、`services/` | 工作流实例与 API 服务实例 |
| `roles/`、`files/`、`databases/` | 角色、任务和数据库模板 |
| `runs/`、`orchestrations/` | 运行快照、历史与编排记录 |
| `combos.json` | 自定义工具组合 |
| `assets.db` | 组织资产与经验 |
| `scheduler/` | 定时任务定义与触发记录 |

常用配置包括 API 服务端口与鉴权、并发上限、运行空闲超时、暂停期限、状态轮询间隔、默认重试上限、任务上下文长度，以及本地或外部嵌入模型。具体字段和默认值见 [组件配置](cordis.patch.yml)。
